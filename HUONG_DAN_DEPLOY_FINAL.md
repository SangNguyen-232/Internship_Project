# Hướng Dẫn Deploy ESP32 IoT — Public Internet (0 Đồng)

## Kiến Trúc Triển Khai

```
ESP32 (bất kỳ mạng WiFi nào)
          │
          │ HTTPS POST /sensor
          ▼
https://xxxxx.trycloudflare.com
          │
          ▼
   Cloudflare Tunnel
   (outbound, không cần mở port router, không cần IP tĩnh)
          │
          ▼
   Node.js — localhost:3000
          │
          ▼
   PostgreSQL — localhost:5432
```

**Tổng chi phí: 0 đồng**
**Điều kiện:** Máy tính chạy Node.js + PostgreSQL + cloudflared phải bật và có Internet.

---

## Yêu Cầu Phần Mềm

| Phần mềm  | Phiên bản    | Dùng cho            |
| ----------- | -------------- | -------------------- |
| Node.js     | 18.x trở lên | Backend              |
| PostgreSQL  | 14.x trở lên | Database             |

# PHẦN 1 — CÀI ĐẶT VÀ CHẠY BACKEND

## Bước 1 — Cài PostgreSQL

**Windows:**
Tải installer tại https://www.postgresql.org/download/windows/ → cài đặt,
nhớ ghi lại password của user `postgres`.

**Ubuntu/Debian:**

```bash
sudo apt update
sudo apt install postgresql postgresql-contrib -y
sudo systemctl start postgresql
sudo systemctl enable postgresql
```

**macOS:**

```bash
brew install postgresql@16
brew services start postgresql@16
```

---

## Bước 2 — Tạo Database, Bảng và Tài Khoản

Đăng nhập PostgreSQL:

```bash
# Linux
sudo -u postgres psql

# Windows / macOS
psql -U postgres
```

Chạy **toàn bộ** đoạn SQL sau theo thứ tự, không bỏ dòng nào:

```sql
CREATE DATABASE iot_db;
\c iot_db

CREATE TABLE "sensor_logs" (
  "id" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "timestamp_real" timestamp,
  "timestamp_up" timestamp NOT NULL,
  "temperature" text,
  "humidity" text,
  "soil_moisture" text,
  "PUMP_state" text,
  "MODE_state" text,
  "Message" text,
  "Score" text,
  "device_id" text,
  "latency" int,
  "trigger_source" text
);

CREATE TABLE device_credentials (
  device_id text PRIMARY KEY,
  password  text NOT NULL
);

CREATE USER iot_user WITH PASSWORD '004232';
GRANT ALL PRIVILEGES ON TABLE sensor_logs TO iot_user;
GRANT USAGE, SELECT ON SEQUENCE sensor_logs_id_seq TO iot_user;
GRANT ALL PRIVILEGES ON TABLE device_credentials TO iot_user;

CREATE TABLE IF NOT EXISTS system_users (
  id         SERIAL PRIMARY KEY,
  username   TEXT NOT NULL UNIQUE,
  password   TEXT NOT NULL,
  role       TEXT NOT NULL CHECK (role IN ('admin', 'user')),
  created_at TIMESTAMP DEFAULT NOW()
);

GRANT ALL PRIVILEGES ON TABLE system_users TO iot_user;
GRANT USAGE, SELECT ON SEQUENCE system_users_id_seq TO iot_user;

INSERT INTO system_users (username, password, role) VALUES
  ('admin', '123456', 'admin'),
  ('user1', '123456', 'user')
ON CONFLICT (username) DO NOTHING;
```

Thoát psql:

```
\q
```

# PHẦN 2 — TẠO CLOUDFLARE TUNNEL (PUBLIC URL)

## Bước 6 — Cài cloudflared

**Windows:**

```powershell
winget install Cloudflare.cloudflared
```

https://github.com/cloudflare/cloudflared/releases/latest
→ chọn `cloudflared-windows-amd64.msi` → cài đặt bình thường.

**Ubuntu/Debian:**

```bash
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb -o cloudflared.deb
sudo dpkg -i cloudflared.deb
```

**macOS:**

```bash
brew install cloudflared
```

Kiểm tra cài thành công:

```bash
cloudflared --version

```

## Bước 7 — Chạy Quick Tunnel

Đảm bảo backend đang chạy (Bước 5), sau đó mở **terminal mới** và chạy:

```bash
cloudflared tunnel --url http://localhost:3000
```

Chờ khoảng 5–10 giây, terminal sẽ in ra:

```

2024/xx/xx INF +--------------------------------------------------------------------------------------------+
2024/xx/xx INF |  Your quick Tunnel has been created! Visit it at (it may take some time to be reachable):  |
2024/xx/xx INF |  https://abc-def-ghi-jkl.trycloudflare.com                                                 |
2024/xx/xx INF +--------------------------------------------------------------------------------------------+

**Ghi lại URL** `https://abc-def-ghi-jkl.trycloudflare.com` — sẽ dùng ở bước tiếp theo.

Kiểm tra: mở trình duyệt vào URL đó → thấy trang login là tunnel hoạt động.

> Giữ terminal này mở. Đóng terminal → tunnel mất → URL không còn hiệu lực.

# PHẦN 3 — SỬA FIRMWARE ESP32

Đây là thay đổi bắt buộc để ESP32 POST dữ liệu lên internet thay vì chỉ
trong LAN.

## Bước 8 — Sửa task_database.cpp

Mở file `src/task_database.cpp`.

**Thêm include ở dòng đầu file** (sau các include có sẵn):

```cpp
#include "task_database.h"
#include <WiFi.h>
#include <HTTPClient.h>
#include <WiFiClientSecure.h>      // ← THÊM DÒNG NÀY
#include "serial_log.h"
#include "task_webserver.h"
#include "pump.h"
#include <sys/time.h>
```

**Xóa đoạn kiểm tra global_admin_ip** (dòng 70–76 trong file gốc):

```cpp
// XÓA TOÀN BỘ ĐOẠN NÀY:
if (global_admin_ip.isEmpty())
{
    serialLogLock();
    Serial.println("[DB] Chưa có IP admin.");
    serialLogUnlock();
    continue;
}
```

**Thay thế 3 dòng build URL và HTTPClient** (dòng 139–143 trong file gốc):

Tìm đoạn:

```cpp
String dbUrl = "http://" + global_admin_ip + ":3000/sensor";

HTTPClient http;
http.begin(dbUrl);
http.setTimeout(5000);
```

Thay bằng:

```cpp
String dbUrl = "https://abc-def-ghi-jkl.trycloudflare.com/sensor";

WiFiClientSecure client;
client.setInsecure();
HTTPClient http;
http.begin(client, dbUrl);
http.setTimeout(10000);
```

> Thay `abc-def-ghi-jkl.trycloudflare.com` bằng URL thực tế nhận được ở Bước 7.
> `client.setInsecure()` bỏ qua xác thực certificate — chấp nhận được cho demo/đồ án.
> Timeout tăng lên 10000ms vì qua internet sẽ có độ trễ cao hơn LAN.

---

## Bước 9 — Build và Flash Firmware

Kết nối ESP32 với máy tính qua USB.

**Qua VS Code PlatformIO:**

1. Mở thư mục firmware trong VS Code
2. Nhấn nút **Build** (dấu ✓) để kiểm tra không có lỗi biên dịch
3. Nhấn nút **Upload** (mũi tên →) để flash firmware

**Qua CLI:**

```bash
cd firmware/

# Build kiểm tra lỗi trước
pio run

# Flash firmware lên ESP32
pio run --target upload
```

> Không cần chạy `uploadfs` lại vì LittleFS (dashboard HTML) không thay đổi.

---

## Bước 10 — Cấu Hình WiFi Cho ESP32 (Lần Đầu)

Sau khi flash xong, ESP32 khởi động và kiểm tra thông tin WiFi đã lưu.

**Nếu ESP32 chưa có WiFi được cấu hình** (lần đầu dùng hoặc sau khi reset):

ESP32 tự động vào **AP Mode**:

- SSID: `ESP32 LOCAL`
- Password: `12345678`
- IP: `192.168.4.1`

Kết nối máy tính hoặc điện thoại vào WiFi `ESP32 LOCAL`, mở trình duyệt vào
`http://192.168.4.1`:

1. Click icon bánh răng ⚙ (Settings) ở sidebar
2. Nhập SSID và password WiFi có Internet
3. Nhấn **Lưu & Kết nối**
4. ESP32 tự restart và kết nối WiFi

**Nếu ESP32 đã có WiFi cấu hình từ trước:** bỏ qua bước này, ESP32 tự kết nối.

## Bước 11 — Kiểm Tra ESP32 Hoạt Động

Mở Serial Monitor (baud rate 115200) trong VS Code PlatformIO hoặc:

```bash
pio device monitor
```

Output mong đợi sau khi kết nối WiFi thành công:

```
Địa chỉ IP chế độ STA Mode: 192.168.x.x
TinyML T=25.0°C H=65.0% S=35% | rule=1 pred=1 | Normal | p=[0.95,...] | 12ms
[DB] POST thành công -> 200
```

Nếu thấy `[DB] POST thành công -> 200` → ESP32 đã gửi dữ liệu lên backend qua internet thành công.

# PHẦN 5 — XỬ LÝ SỰ CỐ

## URL tunnel thay đổi sau khi restart cloudflared

Đây là hạn chế của Quick Tunnel — URL ngẫu nhiên mỗi lần tạo mới.

Khi URL thay đổi, phải:

1. Cập nhật URL mới vào `task_database.cpp` (Bước 8)
2. Build và flash lại firmware (Bước 9)

**Cách giảm thiểu:** Không tắt terminal chạy cloudflared trong suốt thời gian demo. Nếu máy phải restart, chạy lại `cloudflared tunnel --url http://localhost:3000` và flash firmware với URL mới trước khi demo.

---

## ESP32 báo POST thất bại

**`[DB] POST thất bại: connection refused`**
→ Backend chưa chạy. Chạy lại `node index.js`.

**`[DB] POST thất bại: ssl handshake failed`**
→ Thiếu `WiFiClientSecure` hoặc `client.setInsecure()`. Kiểm tra lại Bước 8.

**`[DB] POST thất bại: -1` hoặc `connection timeout`**
→ Tunnel chưa chạy hoặc URL sai. Kiểm tra terminal cloudflared còn mở không,
   so sánh URL trong code với URL tunnel thực tế.

**`[DB] Chưa có IP admin.`**
→ Chưa xóa đoạn kiểm tra `global_admin_ip` như hướng dẫn Bước 8. Kiểm tra lại.

---

## Backend báo lỗi kết nối PostgreSQL

```
Error: password authentication failed for user "iot_user"
```

→ Password trong `index.js` không khớp với lệnh `CREATE USER` đã chạy.
  Kiểm tra dòng `password: '004232'` trong `index.js`.

```
Error: database "iot_db" does not exist
```

→ Chưa chạy `CREATE DATABASE iot_db` hoặc chạy sai database. Thực hiện lại Bước 2.

---

## Admin dashboard không thấy thiết bị

Kiểm tra theo thứ tự:

1. ESP32 có kết nối WiFi không? (Serial Monitor)
2. ESP32 có POST thành công không? (Serial Monitor: `[DB] POST thành công`)
3. Backend có nhận request không? (terminal node.js có in lỗi không)
4. Database có dữ liệu không?
   ```sql
   -- Chạy trong psql
   \c iot_db
   SELECT COUNT(*) FROM sensor_logs;
   ```
